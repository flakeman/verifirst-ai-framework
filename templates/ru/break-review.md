# Проход «Сломай» — чек-лист и промпты

> Проводится в **отдельном** контексте от того, в котором создан результат: новая сессия, другая модель или человек. Цель — доказать, что результат неверен, а не одобрить его.

## Чек-лист

| # | Проверка | Пройдено? | Заметки |
|---|---|---|---|
| 1 | **Критерий готовности** — выполнен каждый критерий из Контракта намерения | ☐ | |
| 2 | **Границы** — ничего не изменено, не додумано и не выдумано за пределами | ☐ | |
| 3 | **Выдумки** — каждый факт, источник, цифра, имя, API существуют и верны | ☐ | |
| 4 | **Логика** — нет противоречий, необоснованных скачков и ошибок в расчётах | ☐ | |
| 5 | **Граничные случаи** — учтены пустые, крайние и необычные, но реальные входные данные | ☐ | |
| 6 | **Расползание задачи** — нет изменений, о которых не просили | ☐ | |
| 7 | **Излишняя уверенность** — неуверенные утверждения помечены как таковые | ☐ | |
| 8 | **Журнал решений** — ничего не противоречит записанным решениям (или это явно отмечено) | ☐ | |

**Вердикт:** ✅ Принять / 🔁 Обратно в «Сделай» (итерация __ из 3) / ⚠️ Пересмотреть контракт

## Готовые промпты

### Общая критическая проверка

```
Ты строгий ревьюер. Твоя единственная задача — найти проблемы в результате ниже.
Не хвали его и не переписывай.

Контракт намерения:
<вставить контракт>

Результат:
<вставить результат>

Проверь: (1) каждый критерий готовности, (2) Границы, (3) выдуманные факты,
источники, цифры или имена, (4) логику и арифметику, (5) граничные случаи,
(6) изменения, о которых не просили, (7) излишне уверенные утверждения.

Верни таблицу: проблема | серьёзность (критично / существенно / мелочь) | доказательство | как исправить.
Если ничего существенного не нашёл — скажи это явно и перечисли, что проверял.
```

### Проверка фактов

```
Выпиши каждое фактическое утверждение из текста ниже нумерованным списком.
Для каждого: можно ли его проверить? Какой источник его подтвердит? Помечай
как НЕ ПОДТВЕРЖДЕНО любое утверждение, которое не можешь подтвердить. Не считай
утверждение верным только потому, что оно звучит правдоподобно.
```

### Код

```
Проверь этот код так, будто завтра он уйдёт в прод, а тебя разбудят, если он упадёт.
Найди: поведение, не соответствующее критериям готовности, необработанные граничные
случаи, выдуманные API или функции, проблемы безопасности и изменения за пределами
задачи. Предложи конкретные тест-кейсы, которые его сломают.
```

### Пре-мортем

```
Представь, что этот результат использовали, и через три месяца выяснилось,
что это была серьёзная ошибка. Напиши три самых вероятных объяснения, что пошло не так.
```

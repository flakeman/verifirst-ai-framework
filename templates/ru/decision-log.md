# Журнал решений

> Один журнал на проект, например `DECISIONS.md` в корне репозитория. Записываем решения, от которых зависит дальнейшая работа, а не каждый шаг. Подаём нужные записи в контекст ИИ при возвращении к проекту.

**Инструкция для ИИ (вставлять вместе с журналом):**
> Это зафиксированные решения проекта. Следуй им. Если что-то из твоих предложений противоречит решению — скажи это явно и назови его ID, а не отступай молча.

---

## Шаблон

```markdown
### D-000 · ГГГГ-ММ-ДД · <краткое название>
- **Решение:** <одно предложение>
- **Причина:** <почему, 1–2 предложения>
- **Отвергнутые варианты:** <вариант — почему отказались>
- **Пересмотреть, если:** <условие, при котором решение открывается заново>
- **Статус:** действует / заменено D-___
```

---

## Пример

### D-001 · 2026-10-08 · Одна база данных
- **Решение:** На этапе MVP все сервисы используют один экземпляр PostgreSQL.
- **Причина:** Команда из двух человек; простота эксплуатации сейчас важнее изоляции.
- **Отвергнутые варианты:** Отдельная база на сервис — слишком много операционных затрат при текущей нагрузке.
- **Пересмотреть, если:** Сервисов больше трёх или одному нужно независимое масштабирование.
- **Статус:** действует

### D-002 · 2026-10-08 · Никаких выдуманных данных в отчётах
- **Решение:** В отчётах, подготовленных ИИ, у каждой цифры должен быть источник; неизвестные значения показываются как «н/д».
- **Причина:** Выдуманную цифру в одном из прошлых черновиков заметил только клиент.
- **Отвергнутые варианты:** Только выборочная ручная проверка — пропускала ошибки.
- **Пересмотреть, если:** Никогда, пока отчётность не переведена на полностью автоматизированный и протестированный конвейер.
- **Статус:** действует

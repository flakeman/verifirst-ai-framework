# Контракт намерения

> Скопируй блок в задачу, issue или промпт. Заполни все поля. Если не получается заполнить **Критерий готовности**, задача не готова к делегированию.

```markdown
## Контракт намерения

**Задача:** <одно предложение>
**Квадрант Карты доверия:** 🟢 / 🟡 / 🔵 / 🔴

### Цель
Зачем это нужно? Какую проблему и для кого решает?

### Критерий готовности
Наблюдаемые, проверяемые условия. На каждое можно ответить «да/нет».
- [ ] ...
- [ ] ...

### Границы
Что НЕЛЬЗЯ менять, предполагать или выдумывать.
- Не менять: ...
- Не предполагать: ...
- Не выдумывать факты, источники, цифры и имена. Если что-то неизвестно — писать «неизвестно» и выносить в открытые вопросы.

### Входные данные и контекст
- Материалы: ...
- Ограничения: ...
- Связанные решения из Журнала решений: D-...

### Проверяющий и способ
- Кто/что проверяет: ...
- Как: тесты / контрольные суммы / сверка с источниками / экспертное чтение / ...

### Формат результата
- Вид: ...
- Дополнительно вернуть: список сделанных допущений и открытых вопросов.
```

---

## Пример

```markdown
## Контракт намерения

**Задача:** Написать SQL-запрос помесячной выручки по регионам за 2025 год.
**Квадрант Карты доверия:** 🟡

### Цель
Финансовому отделу нужна разбивка по регионам для годового отчёта.

### Критерий готовности
- [ ] Сумма по всем регионам равна итогу из таблицы `finance.annual_totals` (±0).
- [ ] 12 месяцев × все активные регионы, без пропусков (ноль, если продаж не было).
- [ ] Возвраты вычтены, тестовые заказы исключены.

### Границы
- Не изменять таблицы; только запросы на чтение.
- Не предполагать соответствие регионов — использовать только `dim_region`.
- Не придумывать названия колонок; если поля нет — спросить.

### Входные данные и контекст
- Схема: приложенный `schema.sql`.
- D-012: тестовые заказы помечены `is_test = true`.

### Проверяющий и способ
- Аналитик запускает запрос и сверяет итоги с `finance.annual_totals`.

### Формат результата
- Один SQL-запрос + пояснение в 3 строки + список допущений.
```

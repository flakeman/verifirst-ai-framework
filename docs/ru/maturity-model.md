# Модель зрелости VeriFirst

[English version](../en/maturity-model.md) · [← К фреймворку](../../README.ru.md)

Модель помогает за 10 минут понять, где команда или компания находится сейчас и какой следующий шаг даст больше всего пользы. Уровни идут по порядку: следующий опирается на предыдущий.

| Уровень | Название | Коротко |
|---|---|---|
| **0** | Стихийный | ИИ используют как придётся; результаты не проверяются системно |
| **1** | Осознанный | Люди различают задачи по риску и проверяют важное |
| **2** | Командный | Проверка встроена в процесс команды: контракты, «Сломай», шаблоны в трекере |
| **3** | Межкомандный | Общие правила для нескольких команд: каталог, R0–R3, долг проверки |
| **4** | Управляемый | Политика на уровне компании, реестр ИИ-систем, отчётность руководству |

---

## Самодиагностика

Отвечайте «да» только если это верно для большинства людей или задач, а не для отдельных энтузиастов. Ваш уровень — **последний, на котором «да» хотя бы на 4 вопроса из 5**, при условии что все предыдущие уровни тоже пройдены.

### Уровень 1 · Осознанный

1. Перед нетривиальной задачей для ИИ люди оценивают, чем грозит ошибка.
2. Результаты ИИ в важных задачах (код в прод, тексты клиентам, цифры для руководства) проверяет человек.
3. Есть общее понимание, что ИИ может уверенно выдумывать факты, источники и названия.
4. Необратимые действия (отправка, оплата, удаление, публикация) ИИ не выполняет без человека.
5. Люди могут привести пример ошибки ИИ, которую они поймали.

### Уровень 2 · Командный

1. Задачи для ИИ ставятся с проверяемым критерием готовности (Контракт намерения или аналог).
2. Для 🟡 и 🔴 задач проверку проводит отдельная сессия, другая модель или другой человек.
3. В трекере есть шаблон или поле для квадранта и критериев (форма задачи, шаблон PR, поле в Jira).
4. Команда ведёт журнал решений и подаёт его ИИ при работе над проектом.
5. Время на проверку закладывается в план (спринт, итерацию), а не делается «по остаточному принципу».

### Уровень 3 · Межкомандный

1. Есть общий каталог типовых задач с назначенными квадрантами.
2. Системы и среды классифицированы по R0–R3 одинаково для всех команд.
3. На стыках команд действуют контракты: что одна команда гарантирует другой в результатах ИИ.
4. Долг проверки учитывается явно (метка, счётчик) и гасится по плану.
5. Ускользнувшие ошибки считаются по командам и разбираются.

### Уровень 4 · Управляемый

1. Есть утверждённая политика: какие квадранты разрешены в каких доменах.
2. Есть перечень R3-действий, которые в компании всегда требуют человека.
3. Ведётся реестр ИИ-систем, влияющих на клиентов или деньги: владелец, квадрант, способ проверки.
4. Руководство регулярно получает отчёт: ускользнувшие ошибки, инциденты, доля затрат на проверку.
5. Требования внешних стандартов или регуляторов сопоставлены с внутренними правилами ([сопоставление](standards-mapping.md)).

## Как перейти на следующий уровень

### 0 → 1: «Начать замечать»

- Провести часовую встречу: 3–4 реальные ошибки ИИ из жизни команды и Карта доверия.
- Раздать [шпаргалку](../../CHEATSHEET.ru.md).
- Подключить [инструкции для ИИ](../../ai-instructions/README.md) в инструменты, которыми уже пользуются.
- Договориться об одном правиле: «необратимое делает только человек».

**Признак успеха:** через месяц люди сами называют квадрант задачи.

### 1 → 2: «Встроить в процесс»

- Добавить [форму задачи и шаблон PR](../../integrations/README.md) в трекер.
- Добавить пункт «Сломай пройден» в Definition of Done для 🟡 и 🔴.
- Завести `DECISIONS.md` в каждом активном проекте.
- Начать считать TTV и ускользнувшие ошибки хотя бы вручную, раз в спринт.

**Признак успеха:** ускользнувшие ошибки обсуждаются на ретро как отдельная тема.

### 2 → 3: «Договориться между командами»

- Назначить ответственного за проверяемость.
- Собрать общий каталог типовых задач (обычно 15–30 строк хватает на старт).
- Классифицировать общие системы по R0–R3.
- Ввести метку `verification-debt` и смотреть её на каждом планировании.

**Признак успеха:** команды проверяют результаты друг друга на стыках, а не только свои.

### 3 → 4: «Сделать управляемым»

- Утвердить политику на одну страницу ([пример](scaling.md#уровень-портфеля--компании)).
- Завести реестр ИИ-систем.
- Ввести квартальный отчёт руководству.
- Сопоставить правила с внешними требованиями, актуальными для отрасли.

**Признак успеха:** решение «можно ли здесь использовать ИИ» принимается по политике за минуты, а не обсуждается неделями.

## Типичные ошибки при внедрении

- **Прыжок через уровень.** Политика компании (4) без командной практики (2) остаётся бумагой.
- **Измерение объёма.** «Сколько людей пользуется ИИ» — не уровень зрелости. Считайте проверенные результаты и ускользнувшие ошибки.
- **Самопроверка как проверка.** Инструкции для ИИ повышают качество, но не заменяют независимый проход «Сломай».
- **Запреты вместо проверяемости.** Запретить ИИ в 🔴 задачах проще, чем сделать их проверяемыми, но пользы меньше. Сначала ищите способ перевести задачу в 🟡.
